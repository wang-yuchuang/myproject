本文说明多语言文案存放在哪里、运行时如何被取出。验收级断言见权威源 R1（含 `Cfg_Parse_Resources` 在 12 个解析函数之列），此处只做叙述与代码定位。

## 文案存在哪里

多语言文案存放在配置库 `System.cfg`（SQLite）的 `Resources` 表，随配置一起下发，代码里没有硬编码的翻译文本。schema 见 `src/config/System.sql:4352`：

| 列 | 含义 |
|---|---|
| `Res_ID` / `Res_Name` | 文案 ID 与语言无关的 key 名（1~32 字符） |
| `Text_Chinese` / `Text_ChineseTrad` | 简体 / 繁体中文 |
| `Text_English` / `Text_Italian` / `Text_German` / `Text_Spanish` | 西文语言列 |
| `Text_Portuguese` / `Text_French` / `Text_AustrianAuth` | 其余语言（含奥地利市场变体） |

引用该表的配置表（外键都指向 `Resources.Res_ID`）：

- `Charger_Devices.Name_Res`，设备名（schema `System.sql:4205`）
- `Charger_DeviceModel_Alarms.Name_Res`，告警名（`System.sql:59`；同表 `Alarm_Name` 是一份不参与翻译的英文名）
- `Web_MainIdx.Name_Resour` / `Web_SubIdx.Name_Resour`，Web 菜单名（`System.sql:9604` / `:9628`）

## 文案怎么被使用

运行时有两条取文案的路径，取到的东西不一样：

1. **内存路径（DPR → DAI → 上报器），拿到的是 key 不是翻译。** 配置加载时 `Cfg_Parse_Resources`（`config_mangmt.c:326`，表注册见 `dpr_loader.c:1298`）只读 `Res_ID` 和 `Res_Name` 两列进内存，语言列不进内存。上报器随后经 DAI 查名称：`DAITYPE_GETDEVNAME_BYID_R`、`DAITYPE_GETAALARMNAME_BYID_R`、`DAITYPE_GETAALARM_LEVEL_BYID_R`（枚举 `dai_model.h:36-38`，实现 `dai_loader.c:143` / `:304` / `:317`），返回 `Res_Name` key 串并截断到 32 字节。调用方分布在 MaintainBE（`maitain_be_msghandler.c:247`、`meb_dev_msghandler.c:75`）、es_iocpp（`:1713`）、ify_cloud（`:1427`）、es_mqtt（`:1532`）等 reporter，用于告警上报的 name / src 字段。接口细节见 [`../30-interfaces/dai.md`](../30-interfaces/dai.md)。
2. **Web 路径（web_reporter 直查 SQL），拿到的是真正的翻译文本。** Web 后端直接执行 `select * from Resources`（`rundata_exchange.c:248`），`Load_LangResources`（`rundata_exchange.c:340`）按会话语言（`session_mgmt.c:68`）装配翻译字典，语言枚举定义在 `basetypes.h:327`（`LANG_TYPE_CHINESE=0` 起）；导出接口还会按列取 `Text_AustrianAuth`（`api_export_pcs.c:298`）。

## 维护注意

- 改文案是改 DB 不是改代码：文案只存在于 `System.cfg` / `System.sql`，调整措辞或补翻译后需重新下发配置，源码无需改动。
- 内存路径（DAI）返回的是 `Res_Name` key 串，不是本地化文本；需要按语言展示的界面应走 web 路径或自行查 `Resources` 表，不要误把 DAI 返回值当翻译。
- ID 查不到时 DAI 不写缓冲、也不报错（`dai_loader.c:146` / `:307` 的循环找不到即跳出），而部分调用方直接传未初始化的 32 字节栈缓冲（如 `maitain_be_msghandler.c:246`），这种情况下上报字段可能带出栈残留。
- `Res_Name` 为 NULL 会被判为配置错误并中止该项加载（`config_mangmt.c:336`，返回 `CFG_ERR_BADCONFIG`）；另外 `System.sql` 只是 schema 参考，各表实际行数以随包下发的 `System.cfg` 为准。
