## Context

本变更来自 2026-09-16 的 spec 全量审核（3 个并行代理 + 人工复核）。`system-hand` 的 R1 / R5 被发现与代码**相反**。

关键在于这两条的**危害等级不同寻常**：

- 多数 spec 缺陷是"信息不足"或"信息不精确"，读者会因缺少依据而停下
- 而 `R1` 写着「**生产部署前必须取消注释**」—— 它**主动指示读者去做一件与既定方向相反的事**（启用整机重启）。这类缺陷**能通过评审**（因为看起来像是"待启用的临时措施"），且一旦照做就会推翻已上板验证的行为（系统连续在线 4h25m、零重启）

`R5` 则是一条"机制描述不可能成立"的缺陷：`fopen(path, "w+t")` 的 `"w"` 语义是**截断或创建**，文件已存在时**同样成功**，因此它**不可能**实现文档所称的"防重复启动"。

## Goals / Non-Goals

**Goals**

- 让 R1 描述**代码真实行为**：心跳丢失 180s → 仅记录 + 重置计数 + `continue`，MUST NOT 重启、MUST NOT 退出
- 把「**MUST NOT** 以'生产前取消注释'为由恢复整机重启」写成**显式禁令**，并指明正确归属（BSP `app_sysmgr` 保活 / 上层 supervisor）
- 让 R5 描述**真实机制**：PID 文件是**供 app 端脚本判断的标记**，防重复启动在 `run_app` 侧（且已用 `pidof syshand`）
- 保持最小改动：块行数不变，使 `git diff` 可作为机械验收判据

**Non-Goals**

- 不改任何代码
- 不动 R2 / R3 / R4（R3 里的 `_SYSTEM("reboot")` 是**应用自己发起的、有意的**整机重启请求，非"故障自愈"，不受本变更影响）
- 不修同 spec 的低价值项（`Version: 0.4` 元数据不一致、行号 +2 偏移、`:224` 的区间标注）—— 另立批次
- 不引入新的 Requirement 或重编号

## Decisions

### D1：只改被证伪的行，并**刻意保持块行数不变**

MODIFIED 是整块替换，delta 里 R1 的 41 行、R5 的 31 行会被逐字写回 canonical。若替换时增删行，`git diff` 就无法用"只应出现 N 处行内变更"来机械验收。

因此所有替换**前后行数相等**（S1c 2→2、S1d 3→3、S1e 3→3、S5a 3→3），验收判据为：

> `git diff` 的内容行变更 **恰好 15 处**（R1 10 + R5 5），且 R1 仍 41 行、R5 仍 31 行

### D2：把"不得恢复 reboot"写成 **MUST NOT 禁令**，而不是删除旧文

若只是删掉「生产部署前必须取消注释」，读者仍可能从别处（如 `handler.c:173`/`:215` 的注释形式）推断"这是待启用的功能"。故显式写入：

> **MUST NOT 以"生产前取消注释"为由恢复整机重启**

并同时给出**正确归属**（BSP `app_sysmgr` 保活 / 上层 supervisor），让读者知道"该由谁负责"而非只被告知"不许做"。

### D3：R5 要写明 `fopen("w+t")` 的**语义陷阱**，而非只改结论

只说"PID 文件不是自锁"不够 —— 读者看代码仍会以为 `fp == NULL` 是重复启动检测。故在 Scenario 里写明：

> `"w"` 语义是**截断或创建**，**文件已存在同样成功** → `fp == NULL` 分支**不可能因"进程已在运行"而触发**（仅路径不可写时触发）

### D4：把"spec 主动诱导错误操作"列为最高危害类别（供后续审核复用）

本轮审核把缺陷分为三类：① 与代码相反的行为描述 ② 清单/ID 不实 ③ 路径与文件归属错位。本变更处理的 R1 属①，但它比一般的①更危险 —— 它**包含祈使句**（"必须取消注释"）。

**判定规则（建议纳入审核清单）**：spec 中出现"必须/需/应在生产前…"这类**祈使句**时，必须逐句对照代码确认该指令**当前是否仍然成立**；陈旧祈使句的优先级高于任何陈述性错误。

## Risks / Trade-offs

| 风险 | 等级 | 缓解 |
|---|---|---|
| MODIFIED 整块替换时抄写偏差静默污染 canonical | 中 | 机械提取+替换+`diff` 自检；归档后 `git diff` 必须只含 15 处行内变更且块行数不变；不符则 `git checkout --` 回退 |
| 删掉"架构演变方向"的规划描述后，读者不知后续规划 | 低 | D2 的替换文本保留了"应用启动/保活归 BSP `app_sysmgr`"的正向归属说明 |
| R3 的 `_SYSTEM("reboot")` 被误认为同类问题 | 低 | 已在 Non-Goals 显式区分：那是**应用有意发起**的重启请求（升级/复位），非故障自愈 |
| 本变更只修 2 条，`system-hand` 仍有低价值偏差 | 低 | 已在 `tasks.md` 4.1 / 4.2 登记，另立批次 |
